# Rahgir research experiment protocol

## Research question

Does route-corridor, preference-aware multi-objective POI selection produce a more useful and diverse set of feasible detour itineraries than distance-only, nearest-feasible and scalar weighted baselines, under the same routing inputs and detour/time constraints?

## Hypotheses (pre-register before the final study)

- H1: NSGA-II yields a better approximation set than the implemented simple baselines on the same small synthetic instances, measured by IGD and hypervolume.
- H2: On human-rated real-route POI sets, preference-aware ranking improves NDCG@K over nearest-distance ranking.
- H3: The complete route/time feasibility layer has zero hard-constraint violations in the evaluated itinerary set.
- H4: Source visibility and an explicit unknown-safety state increase user trust versus an otherwise identical interface. This requires an ethically reviewed user study; the current build has no data to accept/reject H4.

## Data partitions

1. **Synthetic algorithm fixtures** — generated by `research/run_experiments.py`, with fixed seeds. These are only for testing algorithm behaviour and indicator computation.
2. **Live route snapshots** — provider responses from the five named Indian OD pairs, stored with retrieval timestamps, provider identifiers, request parameters, provider response hashes, attribution and licence metadata. Do not fabricate a snapshot when a provider is unavailable.
3. **POI relevance judgements** — independent human ratings with a documented rubric, consent, annotator instructions, disagreement and adjudication. Split by route (not randomly by POI) to reduce geographic leakage.
4. **Safety data** — only authoritative, licensed, timestamped road-segment incident/condition data with documented coverage. Community submissions remain unverified observations and are never a substitute for ground truth.

## Route case matrix

- Ghaziabad → Etawah: route-corridor discovery and detour feasibility.
- Delhi → Agra: major attraction and time-window checks.
- Delhi → Jaipur: longer inter-city route and multi-stop cumulative feasibility.
- Delhi → Mathura: culture/heritage category coverage.
- Mumbai → Pune: regional transfer and cross-region robustness.

For each run, archive the local date/time and timezone, departure time, geocoder, router, POI query, provider/API version if exposed, route distance/time, route geometry, POI OSM IDs and tags, matrix data, itinerary, constraints, and errors. Use fixed request payloads and cache the raw provider response where legal.

## Baselines

- **Nearest-feasible:** select the feasible stops with smallest incremental road-time cost.
- **Category-blind route corridor:** same corridor and hard constraints, but no preference/cultural terms.
- **Weighted greedy:** scalarized utility-per-incremental-cost with weights declared before tests.
- **NSGA-II:** binary selection; route order constrained by route-progress fraction; six objectives.
- **Exact enumeration:** reference Pareto set for small synthetic instances only. Not intended for larger live cases.

A publication-quality comparison should add one or more strong TTDP baselines (e.g., GRASP/ILS, VNS or MCTS variants) after checking their assumptions and implementing them fairly. The starter weighted/nearest heuristics are not state-of-the-art baselines.

## Outcomes and metrics

- Feasibility: percentage of returned routes satisfying detour, total-time, stop-count and supported time-window constraints; hard-constraint violation count must be zero.
- Relevance: Precision@K, Recall@K, MAP@K, NDCG@K, calculated only where human relevance labels exist.
- Discovery: unique-category coverage, category entropy, geographic dispersion, and corridor-category novelty proxy. Keep the proxy separate from validated novelty judgements.
- Route cost: additional road-driving time, additional road distance, total planned time including stops.
- Multi-objective quality: hypervolume with a published reference point and IGD to a clearly defined reference front. Report confidence intervals across seeds.
- Reliability: request success rate, provider timeout/rate-limit rate, missing-field rate, p50/p95 latency on a stated machine and network.
- Evidence: source coverage, age, field completeness, conflict rate and unsupported-claim rate.

## Statistical analysis

Pre-register primary endpoint(s), effect direction and practical significance threshold. Use paired route-level comparisons; use bootstrap confidence intervals by route or a paired non-parametric test when assumptions are not met. Correct for multiple comparisons when testing many metrics. Report all seeds and failures, not only successful runs.

## User study

Obtain institutional ethics review/approval where required. Recruit adults voluntarily; disclose data collection; collect minimum personal data; make participation withdrawable. Compare a conventional route-planning workflow against Rahgir with counterbalanced task order. Record completion time, relevance, trust, perceived effort and satisfaction. Do not simulate or invent user responses.

## Ablation plan

Remove one at a time: user preferences, culture tags, category diversity, metadata-completeness objective, opening-hour feasibility, and route-corridor filtering. For each ablation, retain the same input snapshot, seed, population/generation parameters and constraints.

## Reproducibility checklist

- Code commit hash and package lock.
- OS/Python versions and hardware.
- All random seeds.
- Raw source response and retrieval timestamp.
- Provider terms and attribution snapshot.
- Route query payload.
- Optimizer population/generation/mutation settings.
- Metric implementation and reference point.
- Excluded cases and reasons.
- Dataset card and data licence compatibility.

## Executed synthetic benchmark status (17 November 2026)

The current checked-in run completed with eight fixed synthetic instances, twelve candidates per instance, five NSGA-II seeds, population 64 and 60 generations. The per-instance exact reference front was computed once and reused for paired seed runs. `research/results/paper_benchmark/` contains the 160-row raw CSV, JSON/Markdown summaries and the generated figures. NSGA-II's mean 3D Monte-Carlo hypervolume was 0.255434 and mean 6D IGD was 0.126492. These are synthetic fixture outcomes only. The independent unit for paired inference is the generated instance (n=8), not the 40 repeated runs. See `DATASET_CARD.md` and `docs/TEST_REPORT.md` for the data limitations and execution record.

The five named India route cases remain unexecuted against live providers in the current environment because outbound network access was unavailable. No field or participant study has been conducted. The live-route and human-label hypotheses therefore remain untested.
